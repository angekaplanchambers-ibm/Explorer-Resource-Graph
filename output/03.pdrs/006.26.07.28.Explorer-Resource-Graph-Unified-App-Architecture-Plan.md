## Overview

This plan describes how to combine three distinct front-end examples into a single, unified React/TypeScript app that represents the new Explorer Resource Graph. The goal is a working, interactive prototype — not a production build. It demonstrates the full interaction chain: Explorer table → signal banners/Zap triggers → ControlCenter macro view → Workbench deep investigation, with a graph panel the agent can manipulate through natural language.

**What is being built:**

> A new standalone Vite + React app (`explorer-resource-graph/`) that ports the Agentic TFC interaction model (TF Operator + ControlCenter + Workbench) into an Explorer View surface, layered with the Graph Catalog's graph visualization and LLM-driven UI manipulation.

**The three sources and what each contributes:**

| Source | What it contributes | What is NOT taken |
|---|---|---|
| `030.Agentic_TFC/` | App wiring model (App.tsx state machine), ControlCenter.tsx, Workbench.tsx, signal banner + Zap trigger pattern, SCENARIOS, getGraphData, LANDING_WORKFLOWS, CONTEXT_HINTS | TFCWorkspaceView (replaced by ExplorerView), WorkspacesView (replaced), RunsView (not relevant) |
| `terraform-graph-catalog-main/` | Graph data model (nodes/edges), LLM tool-calling loop + 6 tools, chat response contract (reply + tool_calls + actions), `dispatchChatAction` UI action dispatch, blast-radius visualization logic, graph renderer architecture | D3 (prohibited — graph rendering logic extracted, D3 dependency replaced), Go backend (mock data only in prototype), grant-based auth model (mocked with fixture grant) |
| Skyway Merge synthesis | Confirmed design decisions (table-first, graph supplemental, bottom drawer, Option B IA), zone definitions (DEPENDENCY_PANEL, CONVERSATIONAL_DRAWER, GRAPH_PANEL, Resources type card), product boundary (Explorer = managed resource metadata; InfraGraph = cross-product relationship analysis) | InfraGraph component (separate surface), any on-prem/TFE-specific routing |

**Non-negotiable design constraints (from prior decisions):**

- Table-first. The resource table is primary. Graph is supplemental — minimap or side panel, never replacing the table.
- D3 is prohibited. Graph rendering must use a D3-free library. Recommended: `@xyflow/react` (React Flow) — SVG-native, actively maintained, no security flags.
- Conversational query drawer lives at the bottom, not the right panel. Right panel remains available for TF Operator.
- No Solace. TF Operator (Workbench) is the only adjacent deep-work surface.
- Design fidelity matches `030.Agentic_TFC` exactly: IBM Plex Sans/Mono, dark Meridian panel (`#131313`/`#1a1a1a`), TFC shell tokens (navy `#0c0c0e`, blue `#1060ff`). This is a working prototype at the same visual bar as the Agentic TFC app, not a wireframe.

### App-Level State Machine

```typescript
// Root App state (same pattern as Agentic TFC App.tsx)
{
  workbenchOpen: boolean          // Workbench full-screen modal active
  workbenchVisible: boolean       // Animation state (slide transition 260ms)
  workbenchQuery: string | undefined  // Query pre-bound on Workbench open
  pendingQuery: string | undefined    // Query from ControlCenter trigger (cleared after handled)
  explorerView: ExplorerViewState // Replaces "page" from Agentic TFC
}

type ExplorerViewState = {
  activeType: "resources" | "workspaces" | "modules" | "providers" | "tf-versions"
  filters: ResourceFilters        // workspace_id, resource_type, org_id, attr_filters
  chatOpen: boolean               // ConversationalDrawer expanded state
  graphVisible: boolean           // GraphPanel visible toggle
  selectedResource: string | null // Selected row address (drives DependencyPanel)
}
```

### Data Flow: Natural Language → Graph Manipulation

```
User types query in ConversationalDrawer
  │
  ▼
POST /mock/chat  ← (mocked API with fixture responses)
  │
  ▼
LLM tool-calling loop response:
  { reply: string, tool_calls: [...], actions: [...] }
  │
  ├─ render reply as markdown in drawer
  ├─ render tool_calls as transparency strip
  └─ dispatch each action sequentially:
       actions[n].type:
         "navigate_view"      → setExplorerView({ activeType: ... })
         "focus_workspace"    → graphRef.current.highlightWorkspace(id)
         "show_blast_radius"  → graphRef.current.enterBlastMode(id)
         "show_provider_version" → graphRef.current.filterProvider(source, version)
         "filter_table"       → setExplorerView({ filters: ... })  ← NEW action type
```

### Wiring: ExplorerView → ControlCenter → Workbench

```
ExplorerView
  ├─ onControlCenterTrigger(prebound_query) ← from signal banner Zap
  │    └─ App.setPendingQuery(prebound_query)
  │         └─ ControlCenter.initialQuery = pendingQuery
  │              └─ auto-selects matching OPS_BY_PAGE["explorer"] op
  │                   └─ TriagePanel shows evidence + nextSteps
  │                        └─ nextStep with workbenchQuery
  │                             └─ onOpenWorkbench(workbenchQuery)
  │                                  └─ App.setWorkbenchQuery + setWorkbenchOpen(true)
  │                                       └─ Workbench.initialQuery auto-runs scenario
  │
  └─ onRowZapTrigger(row_context) ← from per-row Zap button
       └─ same path as above
```

### Phase 4: Graph Panel + LLM-Driven UI Manipulation

**Status**: [x] done

**Intent**
Build the supplemental `GraphPanel` component that lives alongside the resource table, and wire the `ConversationalDrawer` to dispatch LLM actions to the graph. This is the phase that demonstrates the core product differentiator: natural language manipulates the graph view.

**Steps**
1. Create `src/mock/mockGraph.ts`:
   - Fixture workspace nodes (8 workspaces: networking-prod-core, payments-prod-us-east, api-gateway-prod, etc.)
   - Fixture workspace edges (cross-workspace remote state consumption)
   - Fixture resource nodes per workspace (5-10 per workspace)
   - Fixture provider nodes
2. Create `src/mock/mockChat.ts`:
   - Fixture LLM responses for 6 scripted queries (one per tool/action type):
     - "show blast radius of networking-prod-core" → `show_blast_radius` action
     - "find all aws_instance resources" → `filter_table` action + list_resources tool call
     - "go to providers view" → `navigate_view` action
     - "focus on payments-prod" → `focus_workspace` action
     - "show workspaces using aws 4.67" → `show_provider_version` action
     - "what depends on aws_vpc.main" → `get_dependents` tool call (no UI action)
   - Each response: `{ reply: string, tool_calls: [...], actions: [...] }`
3. Create `src/types/chat.ts` — `ChatMessage`, `ChatResponse`, `UiAction`, `ToolCall`
4. Create `src/components/GraphPanel.tsx` using React Flow:
   - Three view tabs: Workspaces | Resources | Providers
   - Workspace view: nodes sized by resource count, edges as remote-state arrows
   - Resource view: workspace + its resources, dependency edges
   - Provider view: provider nodes + consuming workspace nodes
   - `forwardRef` with imperative handle:
     ```typescript
     export interface GraphPanelHandle {
       highlightWorkspace(id: string): void
       enterBlastMode(id: string): void
       filterProvider(source: string, version?: string): void
       switchView(view: "workspaces" | "resources" | "providers"): void
       fitView(): void
     }
     ```
   - Grayscale palette (no brand colors); highlight nodes use amber/gold
   - User interactions: click node → updates table filter; zoom/pan
5. Create `src/components/ConversationalDrawer.tsx`:
   - Collapsed state: affordance strip ("Ask about your infrastructure ↑") + 3 suggestion chips
   - Expanded state: input field + send button + message thread + tool_call transparency strip
   - On send: POST `mockChat(query)` → render reply → dispatch UI actions sequentially to `graphPanelRef`
   - Agent-driven filter action applies to `explorerView.filters` state (updates table)
6. Wire `graphPanelRef` from `ResourceResultPage` → pass to `ConversationalDrawer`
7. Verify: type "show blast radius of networking-prod-core" → drawer shows reply + tool_calls → graph enters blast mode highlighting (networking-prod-core gold, hop-1 amber, others dimmed) → reply text describes the blast radius

**Expected Outcome**: The ConversationalDrawer is functional with scripted responses. Natural language queries manipulate the graph panel. The blast-radius query both answers in text AND visually highlights the graph. The table filter action visually filters the resource table.
