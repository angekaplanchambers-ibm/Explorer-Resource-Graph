## TL;DR

Gabrielle's Agentic_TFC repo is a Figma-to-code prototype of the Terraform Control Center MVP - an agentic intent layer for HCP Terraform / Terraform Cloud. It implements three surface levels: a persistent global control bar, a default/macro visibility panel, and a full-screen workbench. The repo includes a working React/Vite/shadcn prototype, a detailed MVP product brief (by Gabrielle), and a positioning one-pager. The core design stance is "dehumanized by design" - machine-state language, no chat metaphors, trust earned through operational clarity.

## Key Discussion Points

### Product thesis

Terraform Control Center is an intelligent control surface for Terraform Cloud. It should make Terraform feel more aware of the user's environment without implying autonomous infrastructure decisions. The experience should feel like a Terraform-native control surface: useful, technical, and safe by default. Not a chatbot, not an autonomous operator.

### Three-level architecture

| Level | Name | Role |
|---|---|---|
| 1 | Control bar | Persistent bottom-anchored entry point across all TFC pages |
| 2 | Default / macro view | Fixed-height panel above current TFC page - visibility and orientation |
| 3 | Workbench | Full-screen takeover for deep investigation, verification, workflow prep |

The three levels map to a simple progression: **Entry → Visibility → Depth**

### Core design stance: dehumanized by design

Trust comes from machine-state clarity, not conversational personality.

**Use:** "3 failed runs detected", "Checking policy results", "Approval required"
**Avoid:** "I found 3 failed runs for you", "Let me check that", "How can I help?"

The system should communicate state, constraints, evidence, and next valid actions. No avatars, typing indicators, emotional reassurance, or assistant metaphors.

### Control bar behavior

- Anchored to the bottom of the TFC UI, persistent across all pages
- Supports natural language intent: "Find failed production runs", "Inspect drift in payments workspaces"
- Translates intent into structured Terraform results - not chat bubbles
- Recommended placeholder: "Search, inspect, or prepare infrastructure changes"
- Avoid: "Ask AI", "Chat with Terraform", "How can I help?"
- Feature name shown: "Terraform Control Center" (like AWS CloudShell)

### Progressive escalation interaction model

1. **Find** - navigation and lookup. Returns filtered workspace/run lists
2. **Inspect** - lightweight understanding. Returns failed phase, blocking policy, cost delta, next actions
3. **Prepare** - context binding and recommendations. Binds targets, detects drift, groups resources, generates packets
4. **Execute** - mutating workflows requiring approval, checks, and traceability

### Default / macro view behavior

- Fixed-height panel - does not take over the full screen
- Surfaces estate-level signals: failed runs, policy failures, drift, pending approvals, high-risk plans, provider upgrade opportunities
- Context-aware: if opened from a workspace or run view, uses that as a starting point
- Action pathways: Inspect failed runs, Review policy failures, Investigate drift, Open workbench, Resume recent work

### Workbench behavior

- Full-screen takeover - for immersive deep work
- Structured around Terraform objects, task context, user intent
- View adapts based on what the user is trying to understand
- Verification is central: users can inspect source data, see which Terraform objects are involved
- Input area stays available but does not dominate - the adaptive work surface is the main value
- Sessions: complex work becomes a durable session (drift remediation, provider upgrade, workspace creation)

### Contextual entry points (embedded in existing TFC surfaces)

- Failed run → "Inspect failure"
- Policy failure → "Prepare exception packet"
- Drift detection → "Prepare remediation"
- Workspace → "Review workspace health"
- Provider version → "Plan upgrade"
- Apply → "Export evidence"

### Prototype components implemented

- `ControlCenter.tsx` - the global control bar component
- `Workbench.tsx` - the full-screen workbench
- `TFCWorkspaceView.tsx` - the underlying TFC workspace UI (overview + runs pages)
- `TFCSidebar.tsx` / `TFCTopNav.tsx` - TFC chrome
- `WorkspacesView.tsx` / `RunsView.tsx` - workspace and run list views
- Figma-exported SVG/TSX imports: GlobalControlBarPrototype, WorkspaceOverview, WorkspaceRuns, RadioSelectDataTable, SessionHistory, MeridianV115, Body

### Interaction principles (from MVP brief)

1. **Use system-state language** - "3 failed runs detected" not "I found 3 failed runs"
2. **Keep users oriented** - always show where they started, what context is active, what object they are on
3. **Show structure before prose** - cards, tables, logs, diffs, object references first; prose only to clarify
4. **Keep actions bounded** - inspect, search, summarize, compare, prepare, resume, export, route for MVP; execution and autonomy handled carefully
5. **Make intelligence practical** - relevant signal + clear explanation + well-placed next move is enough

### What MVP should prove

- Users understand the control bar as a Terraform-native entry point (not a chatbot)
- The default / macro view helps users see what matters
- The workbench gives users somewhere useful to go deeper
- The three-level model is understandable across teams
- Teams can extend the pattern without inventing new agentic UI each time

---

## Decisions

- Product experience is dehumanized by design - machine-state language throughout
- Three-level architecture is the canonical model: control bar → macro view → workbench
- The control bar is NOT a chat bar - it is a technical control surface
- MVP prioritizes depth over breadth in the workbench; a small set of key workflows first
- Meridian provides orchestration patterns; the user-facing layer remains native to Terraform
