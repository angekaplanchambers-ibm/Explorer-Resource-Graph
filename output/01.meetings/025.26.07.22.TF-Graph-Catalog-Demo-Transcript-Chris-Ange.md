# TF Graph Catalog Demo — Transcript: Chris Arcand & Ange Kaplan-Chambers

**Date**: July 22, 2026 (8:56 PM, 27m 12s)
**Participants**: Ange Kaplan-Chambers (design, facilitator), Chris Arcand (engineering, Graph Catalog author)
**Context**: Ange requested the meeting to discuss Graph Catalog after it generated significant internal interest. She had watched the full demo recording and reviewed all supporting documentation before the call.

---

## TL;DR

### Ange Kaplan-Chambers — Key Talking Points

- Reviewed Chris's Graph Catalog demo and supported documentation in depth because it generated significant internal interest.
- Shared that she designed Skyway and is leading work on Explorer View and related Terraform experiences.
- Plans to incorporate concepts from the demo into Explorer View, adapting implementation to fit product and security requirements.
- Questioned the fundamental user value of graph visualizations beyond their appeal to stakeholders, focusing on practical user outcomes.
- Argued that Explorer View's core value is metadata exploration, querying, exporting, and comparison workflows, which should remain table-first.
- Suggested the graph should act as contextual support after users investigate data, rather than being the primary experience.
- Saw strong value in AI/LLM-driven UI manipulation and conversational querying, especially for exploring complex metadata and graph relationships.
- Described broader Terraform work around agentic experiences, conversational query interfaces, and integration with IBM's Solace framework.
- Proposed integrating the demo's AI-powered graph manipulation capabilities into Explorer View.
- Framed her approach as selectively extracting the most impactful elements from the demo rather than reproducing the entire Graph Catalog concept.
- Emphasized that Explorer View has significant potential and should evolve into a richer, more compelling experience.

### Chris Arcand — Key Talking Points

- Explained that Graph Catalog was intentionally built as a provocative demonstration rather than a product-ready feature. Described it as partly "clickbait" to drive attention toward InfraGraph concepts and graph-based thinking.
- Noted ongoing leadership discussions about InfraGraph's future direction and whether it should remain Terraform-focused or evolve into something broader.
- Distinguished between a Terraform-specific graph experience and a larger unified knowledge graph vision (UKG) that spans infrastructure, applications, and configuration data - and noted that Terraform is not well suited for the latter.
- Argued that the visual graph itself is the least important part of the demo. The real value is answering user questions and exposing relationships in infrastructure metadata.
- Used blast radius analysis as an example: the graph is a supporting visualization, not the primary interface. Compared it to a code editor minimap - useful for macro-level orientation, not for actual work.
- Agreed that AI-driven manipulation of visualizations was one of the most promising discoveries from the project, and more useful than he originally expected.
- Encouraged adoption of the demo's ideas, not the demo itself. Repeatedly stressed "don't ship Graph Catalog" and instead build polished product experiences around the underlying concepts.
- Emphasized that Terraform already contains the state and configuration data needed to enable these experiences without major architectural changes.
- Pushed back on assumptions that metadata or graph-enabled experiences require massive engineering investments, encouraging teams to move faster.

### Shared Alignment

- Table-based metadata exploration should remain the foundation.
- Graph visualizations are most useful as context and explanation layers, not primary workflows.
- Conversational AI and agentic interactions are a compelling way to query infrastructure relationships and manipulate views.
- The strongest outcome is to extract and integrate the demo's best ideas into Explorer View and Terraform experiences rather than shipping Graph Catalog as a standalone product.
- The goal is to create valuable user experiences that solve real infrastructure understanding and blast radius problems.

## Key Exchanges (from transcript)

**On why D3 was used in the demo:**
> "it is called the graph catalog very intentionally. Like the whole point was to get people to be like, wait a second, you wrote a graph thing. That's what InfraGraph is for. Wow, like. It was clickbait." — Chris Arcand

**On InfraGraph's future:**
> "There are lots of discussions happening at the leadership level on what to do with InfraGraph and what that means... Should it return to its roots of Terraform as being a graphical exploration of Terraform state and configuration? Similar to the UKG... ultimately, someone needs to decide which way the cookie crumbles." — Chris Arcand

**On the value of the graph visualization:**
> "Of all the things shown in that demo, the fact that it's a cool D3 visualization type of thing is actually the lowest priority in that whole thing... It's more of a grounding visualization of like the answer that you're getting from the other pieces." — Chris Arcand

**The minimap analogy:**
> "It's like the minimap feature [in text editors]. It's kind of a supplement. It's not really like actually giving me the direct value for the question that I have. But it certainly helps concretely show in my visual mind of the problem area." — Chris Arcand

**On table-first design:**
> "I still want Explorer View to be table view first. That's what's made it really successful over time. But I think the graph visualization part is for people who need that creative control over it... to supplement what they're looking at." — Ange Kaplan-Chambers

**On LLM UI manipulation:**
> "I like having an LLM manipulate the view, I think it's very powerful." — Ange Kaplan-Chambers
>
> "Yeah. I like that a lot. That actually is something that I discovered in doing this PoC. Like I put it in there because everyone wants AI and I'm trying to come up with a useful thing that it actually does." — Chris Arcand

**On Solace and real estate:**
> "We are talking about what people are loosely calling a chat experience, but what I call a call and response experience... that's going to be something that will probably exist along the bottom instead of the side panel because if we're integrating Solace as well, like that takes up the right real estate." — Ange Kaplan-Chambers

**Chris's direct message to teams:**
